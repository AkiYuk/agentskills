## 概要

プロジェクトの基本ルールとなるCLAUDE.mdを作成し、チケット駆動開発の運用基盤を整備する。

## 背景・目的

- リポジトリが新規作成された状態で、開発ルールが未定義である
- コーディング規約・Git運用・コミュニケーションルールを明文化し、開発の一貫性を確保する
- チケット駆動開発を導入し、要件定義・設計を固めてから実装に入るフローを確立する

## 要件定義

- [x] 日本語ベースのコミュニケーションルールを定義する
- [x] コーディング規約を定義する
- [x] Git運用ルール（ブランチ戦略・コミットメッセージ形式）を定義する
- [x] チケット駆動開発のワークフローを定義する（todo / in-progress / review / done）
- [x] チケット番号の採番ルールを定義する（TICKET-XXX形式）
- [x] Markdownベースのチケットテンプレートを作成する
- [x] チケットとブランチ・コミットの連携ルールを定義する

## 設計

### 変更対象

| ファイル | 変更内容 |
|----------|----------|
| CLAUDE.md | 新規作成。プロジェクトルール全体を記載 |
| tickets/_template.md | 新規作成。チケットのテンプレート |
| tickets/in-progress/TICKET-001.md | 新規作成。本チケット自体 |

### 設計方針

- CLAUDE.mdにプロジェクト全体のルールを集約する
- チケットはステータス別ディレクトリで管理する（`tickets/todo/`, `in-progress/`, `review/`, `done/`）
- チケット番号は3桁ゼロ埋め連番（TICKET-001, TICKET-002, ...）
- ステータスの遷移: `todo` → `in-progress` → `review` → `done`
- ブランチ名にチケット番号を含める（`feature/TICKET-XXX-概要`）
- コミットメッセージにチケット番号を含める（`feat(TICKET-XXX): 内容`）
